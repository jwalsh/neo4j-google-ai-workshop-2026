The non-interactive equivalent is a service-account key for the lab project (gcloud auth activate-service-account --key-file), which Vocareum does not hand out. Not attempted: this machine's gcloud is the owner's and stays out of the lab.
Lab 2, Deploy Neo4j [blocked]
  Create a client credential in the Aura console (Account settings, Client credentials, Aura API). POST https://api.neo4j.io/oauth/token with basic auth client_id:client_secret and grant_type=client_credentials for a one-hour bearer token. GET https://api.neo4j.io/v1/tenants for the project id. Then the request in :evidence. The response carries the password, once. Poll GET /v1/instances/<id> until status is running, and do not resolve the hostname before then (finding 12). Not sent from here by instruction: the credential is made in the console, and an instance made this way lands in whichever organization the credential belongs to, which is the open question of findings 13 and 22. Nothing in this namespace sends it.

Lab 7, Deploy Neo4j Agent [blocked]
  The lab adds a marketplace agent to a new Gemini Enterprise app. Google documents that path as console steps only. A custom A2A agent can be registered by REST: POST https://<location>-discoveryengine.googleapis.com/v1alpha/projects/<project>/locations/<location>/collections/default_collection/engines/<app>/assistants/default_assistant/agents with displayName, description and a2aAgentDefinition.jsonAgentCard. That needs a Google access token for the lab account with the Gemini Enterprise Admin role, an existing app, and the agent's card, which the marketplace listing does not publish. The lab account's token exists only in the lab browser.

Lab 9, Aura Agents [blocked]
  "Create with AI" has no documented API; the nearest thing is importing an agent from JSON, also in the console. Needs: the agent made in the console, External access (which is charged), and an Aura API client credential.
