#+TITLE: 008 - A local graph to explore before the cloud one
#+DATE: 2026-10-08

* Source

The owner's question: what does local development look like for this kind
of data, with other tools, before any cloud instance. It came with a page of
notes on engines and Emacs packages, all unverified; they are the claims
table below. The data is Lab 4's day of Form 13 filings,
=data/form13-2023-05-11.csv=, and the load is the lab's four files in
=labs/lab-04/=. Everything so far ran against a hosted Aura instance that
expires tonight.

* Hypothesis

The lab's load can run on this laptop with nothing installed system-wide,
be checked by the repository's own =workshop.form13/verify= through the
repository's own driver wrapper, and be driven from CIDER and Org the way
=dev/explore.clj= drives Aura.

* Gate

=workshop.form13/verify= on a local database returns =:loaded? true=: 2,251
Company, 28 Manager, 7,381 OWNS, the counts the file implies. Reached
through =workshop.neo4j/connect= with an explicit env map, never =.env=.

The one to use is the first: =org.neo4j/neo4j= from Maven Central is the
whole Community server as a library, started from Clojure with Bolt on
=localhost:7688=. =clojure -M:gate= is the proof; =dev/local_graph/explore.clj=
and =explore.org= are the working surfaces.

What had to change for Neo4j Community (=cypher/01= to =04=):

- =IS NODE KEY= became =IS UNIQUE=. Node keys and existence constraints are
  Enterprise; Aura is Enterprise. This is the only change to the Cypher that
  was forced.
- The https URL became =$csvUrl=, a =file:= URL to the copy in =data/=. Not
  forced: the lab's https statements run locally. Chosen because the load
  then takes 2 s and no network, and because attempt 8 below is what the
  network can do.
- The caller changed, not the statement, for =CALL (row) { } IN
  TRANSACTIONS=: Neo4j refuses it inside a managed transaction, which is
  what =workshop.neo4j/query= opens. =local-graph.lab/run-file= sends such
  statements through an auto-commit session.

* Emacs

Checked with =emacs --batch= (Emacs 32.0.50, Org 9.8.7) and an init
directory under =scratch/=, reading packages from =~/.emacs.d/elpa= and
writing nothing there. Nobody opened a window. Interactive use was not
exercised: no =cider-jack-in=, no =C-c C-c=, no font-lock looked at.

- Installed in =~/.emacs.d/elpa=: cider, clojure-mode, lsp-mode, and CIDER's
  dependencies. None of cypher-ts-mode, cypher-mode, ob-cypher, n4js.
- All four are on MELPA today, at the versions in the table above.
- cypher-ts-mode byte-compiles, its grammar (=taekwombo/tree-sitter-cypher=)
  built into =scratch/treesit=, and the mode turns on. The grammar is
  openCypher 9: every one of the lab's four load files parses with ERROR
  nodes, at =CONSTRAINT= in one and at =LOAD CSV= in three. Whether the
  highlighting is still good enough to read is a question for eyes.
  To try it: =(package-install 'cypher-ts-mode)=, then
  =M-x cypher-ts-mode-install-grammar=.
- cypher-mode, n4js and ob-cypher byte-compile and load on Emacs 32, with a
  missing lexical-binding warning each. ob-cypher was not run against the
  local server. It has two transports, the =/db/data/transaction/commit=
  HTTP path and the =neo4j-shell= program; neither is part of what was
  started here, and from memory both went with Neo4j 4.
- =ob-clojure= ships with Org and is what this repository wants. Two things
  bit, both recorded in =explore.org=: its backend defaults to babashka
  here, so the file sets =:backend cider=; and it wraps a block's body in
  one form, so a =require= and a use of its alias cannot share a block.
- =ob-cypher-cider.el= in this directory gives real =#+begin_src cypher=
  blocks, with =:var= as parameters, by handing the body to the REPL. It
  byte-compiles, and its blocks ran in batch.
- =explore.org= holds seven results, written by the batch run through a
  CIDER connection to =clojure -M:dev:repl=: three Clojure, two Cypher, two
  sh blocks through =bin/cypher-shell=.
- =.dir-locals.el=: its values were applied in batch under
  =enable-local-variables :safe=, so opening a file here will not prompt.

* What the failures say

- Attempts 2 and 9 are the ones to keep. A local Community server is not a
  small Aura: the lab's first statement is an Enterprise feature, and a
  load written against the local one will run on Aura while a load written
  for Aura will not run here. The constraint that stopped the Graph Builder
  in experiment 005, attempt 6, would not have existed locally.
- Attempts 2, 3 and 12 are about this repository, not about the engines.
  =workshop.form13/load!= has only ever taken its already-loaded branch
  (=.meta/README.md= says so). Run for real it would stop at the fourth
  file, by the rule Neo4j stated in attempt 2; that was not tried against
  Aura. =verify= reports a half load as an empty database. =query= cannot
  be pointed at a database by the map given to =connect=. None of the three
  was changed: =src/= was out of bounds here.
- Attempt 16: "Bolt-compatible" and "accepts the syntax" are two claims,
  and neither is "behaves the same". Memgraph took the lab's statement and
  was a hundred times slower on it than on its own idiom.
- Attempt 8: a local file is not only faster.

* Recommendation

For exploring data of this size before there is a cloud instance: embedded
Neo4j Community in the REPL. It is the lab's engine and the lab's Cypher,
it needs nothing this machine lacks, it starts in the time CIDER takes to
connect, and the database's lifetime is the REPL's. Before even that,
=workshop.form13= on the parsed file, and experiments 002 to 004, answer
most questions with no database at all; the graph earns its place at the
first variable-length path.

Write constraints as =IS UNIQUE= locally and expect to tighten them to node
keys on Aura. Keep =verify= as the check that both hold the same thing.

A container is worth it only for a server other tools must reach, or for a
second engine. Memgraph is the fast one here and the one that needs the
load rewritten. A Kùzu-family engine was not tried; by its documentation it
would need a schema declared first, which for this data is a different
exercise from the lab's.

What the cloud instance is still needed for: node keys and existence
constraints as the lab writes them; Bloom (Lab 5) and the Graph Analytics
session behind its centrality; Document Intelligence and the Aura Agent
(Labs 6 and 9); the Query API that =gmake cypher= falls back to; and
anything Gemini Enterprise has to reach (Labs 7 and 8), which cannot see
=localhost=. None of those was looked for locally.

* What it is not

Not Aura, and not Enterprise: the Enterprise image wants a licence accepted
and was not run. Not a benchmark: one small file, cold JVMs, single runs,
and a podman VM with 4 GB between the containers and the hardware. Not a
test of Kùzu, LadybugDB, RyuGraph, FalkorDB or AGE, none of which ran. Not
checked in a live Emacs. Not a fix for the three things attempt 2, 3 and 12
found in =src/workshop/=. =neo4j:5=, the tag the notes name, was not
pulled. The graph data science library, APOC and vector indexes were not
tried on the embedded server. The Org results are from one batch run;
=explore.org= will be rewritten the first time someone executes it by hand.
