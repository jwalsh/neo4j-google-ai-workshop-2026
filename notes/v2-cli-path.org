and that cost a misplaced click, a stray keystroke run as a statement and a
tab that hung (=.meta/findings.md=, entries 14 to 17 and 23). This is each

that run here.

map, ={:lab :title :status :evidence :how}=, and =(workshop.labs/run-all)=
returns all of them. =dev/labs_explore.clj= walks them one form at a time.
Nothing in it deletes or overwrites, and with no options nothing in it
writes at all.

* Lab 2 - Deploy Neo4j

- In the console :: the marketplace listing, "Manage on provider", Aura's
  sign-up, Professional, "Create instance" (=notes/lab-02-deploy-neo4j.org=).
- By code :: the Aura API. From its documentation:
  1. Create a client credential in the Aura console: Account settings,
     Client credentials, Aura API. The secret is shown once.
  2. A token, good for an hour:
     #+begin_src sh
     curl --request POST 'https://api.neo4j.io/oauth/token' \
          --user "$AURA_CLIENT_ID:$AURA_CLIENT_SECRET" \
          --header 'Content-Type: application/x-www-form-urlencoded' \
          --data-urlencode 'grant_type=client_credentials'
     #+end_src
  3. =GET https://api.neo4j.io/v1/tenants= for the project's id. The API
     still says tenant where the console says project.
  4. =POST https://api.neo4j.io/v1/instances= with a bearer token and
     #+begin_src json
     {"version": "5", "region": "us-east1", "memory": "2GB",
      "name": "My instance", "type": "professional-db",
      "tenant_id": "<project id>", "cloud_provider": "gcp"}
     #+end_src
     The field names and =professional-db= are from the documentation's
     own example, which uses =europe-west1= and =8GB=. That =2GB= and
     =us-east1= are accepted for this tier is taken from the instance the
     console made, not from the specification: the specification page
     renders in a browser and did not come back as text.
  5. =GET /v1/instances/<id>= until =status= is =running=. The response to
     the create carries the password, once. Do not resolve the hostname
     before then (finding 12).
  The same through =aura-cli instance create --name ... --cloud-provider gcp
  --region us-east1 --memory 2GB --type professional-db --tenant-id ...=.
  =(workshop.labs/aura-instance-request "<project id>" "My instance")=
  returns the request as data. Nothing sends it.
- Run here :: no. The credential is made in the console and was not sought.
  One thing this would not settle: an instance made through the API lands in
  the organization the credential belongs to, and which organization that
  should be is the open question of findings 13 and 22.

* Lab 5 - Bloom

- In the console :: Bloom, a search for Manager, OWNS, Company, then
  Degree Centrality from the data science panel, which starts a Graph
  Analytics session, and size scaling (=notes/lab-05-bloom.org=).
- By code, the count :: degree is a count. =(workshop.labs/lab-5)= takes it
  in Cypher for every manager and every company and compares each with the
  same count from the file. Run here: yes, all 28 managers and all 2,251
  companies agree. This is over the whole graph, where Bloom's scene stops
  at 1,000 paths. The picture, nodes sized on a scene, has no equivalent
  and none is claimed.
- By code, the algorithm :: the instance lists =gds.graph.project=,
  =gds.degree.stream= and =gds.session.list= and =delete=: the Cypher API
  for Aura Graph Analytics. From its documentation a projection that names
  a memory size starts a session, with the database's own credentials and
  no Aura API key:
  #+begin_src cypher
  CALL gds.graph.project('lab5', ['Manager', 'Company'], 'OWNS', {memory: '4GB'})
  YIELD nodeCount, relationshipCount;
  CALL gds.degree.stream('lab5') YIELD nodeId, score
  RETURN gds.util.asNode(nodeId).managerName AS manager, score
  ORDER BY score DESC LIMIT 10;
  CALL gds.session.list() YIELD name, memory, status;
  CALL gds.session.delete('<name>') YIELD deleted;
  #+end_src
  Run here: no, and so these four statements have never executed. The
  first starts billed compute on a trial whose bill nobody here can see.
  The documentation's own examples use =gds.pageRank.stream=; that
  =gds.degree.stream= takes the same form is read from the procedure list,
  and =gds.util.asNode= in a session is an assumption. The page also lists
  =gds.graph.project= among unsupported catalog procedures while using it
  in its examples.
- By code, the other way :: the =graphdatascience= Python client,
  =GdsSessions(api_credentials=AuraAPICredentials(client_id, client_secret,
  project_id))= and =sessions.get_or_create(session_name, memory,
  db_connection, ttl)=. That needs the Aura API credential, so it is blocked
  as Lab 2 is.

=CALL gds.session.list()= as user =neo4j= returned no rows. Whether the
session Bloom left running is gone, or is the console user's and not shown
to this one, it does not say.
