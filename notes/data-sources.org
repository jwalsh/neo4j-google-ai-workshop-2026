#+TITLE: Other data sources
#+DATE: 2026-10-09

The owner's question: "think of other data sources we could pull", for a
local-first, REPL-driven framework that is not tied to the workshop's one
file. Fifteen candidates, each fetched on 2026-10-09 unless the row says
otherwise. Nothing here is from the lab or the slides; it is ours.

* The bar

What =form13-2023-05-11.csv= has, and what a replacement is judged against:

| property             | the day file                                              |
|----------------------+-----------------------------------------------------------|
| public, no key       | yes, one GET                                              |
| one file             | 1,126,960 bytes, CSV with a header                        |
| shape                | bipartite: 28 Manager, 2,251 Company, 7,381 OWNS          |
| oracle               | the file: distinct keys are the expected counts           |
| dirt                 | 258 CUSIPs under more than one company name               |
| paired text          | two pages of Apple's 10-K                                 |
| scale                | maps in memory, about two seconds into an embedded Neo4j  |

* How this was checked

"Verified" means a request made on 2026-10-09 returned what the row says:
headers for size and date, and for anything under 50 MB the file itself,
opened and counted. "Recalled" means from memory, not checked. Downloads
went to a scratch directory, not =data/=.

Not verified by request, all recalled:

- Licences for SEC and FEC data (US government works), OpenAlex and Wikidata
  (CC0), deps.dev (CC-BY 4.0), GH Archive (CC-BY 4.0). No page fetched said so
  in words that were read.
- The inside of SEC's official Form 13F zip: 100 MB, over the limit, not
  opened. Its table names below are recalled.
- OpenAlex's abstract field, Wikidata's User-Agent policy, FEC's restriction
  on using individual contributors' names for solicitation.
- Anything about OpenStreetMap beyond one size header: two Overpass servers
  failed (504, then 500).
- The row count of =form13-2023.csv=; estimated from bytes per row.

* Financial filings

** 1. Form 10-K sections, already in the bucket

- URL: https://storage.googleapis.com/neo4j-datasets/hands-on-lab/form10k.zip
- Verified: downloaded and opened. 5,624,228 bytes, updated 2023-09-29.
  94 files (plus 94 macOS =__MACOSX= shadows), 21 MB unzipped. Each is one
  JSON object with keys =item1=, =item1a=, =item7=, =item7a=, =companyName=,
  =cusip=; the file name is the accession number.
- Licence: none stated on the object. The text is from SEC filings.
- Yields: =(:Filing {accession})-[:FILED_BY]->(:Company {cusip})=, 94 and 48.
  35 of the 48 CUSIPs are in the day file. Sections become chunks if wanted.
- Oracle: 94 documents, 48 distinct CUSIPs, 35 matching Company nodes. For an
  extraction, nothing: that is the lesson of Lab 6, and of experiment 006.
- Paired text: it is the paired text. Median 198,000 characters a filing.
- Questions:
  1. Which managers hold a company whose risk factors mention a given word?
     (template, once the text is indexed)
  2. Which companies name each other in Item 1? (extraction, then a template)
  3. Which holdings are most similar by what their filings say?
     (algorithm: node similarity or kNN over embeddings)
- Dirt: one file is a table of contents, 271 characters, for General
  Electric. Company names are lower-cased after the first letter
  ("General electric co"). Several years per company, so CUSIP is not a key
  for Filing. The macOS shadow files are in the zip.
- Breaks: nothing in size. "One file" becomes "one zip of JSON", and a
  whole filing does not fit a small local model's context.
- Also there: =form10k/form10k-clean-all-companies.zip= (215 MB) and
  =form10k/form10k-doc-embeddings.csv= (1.2 GB). Listed, not opened.

** 2. Form 13, the year

- URL: https://storage.googleapis.com/neo4j-datasets/hands-on-lab/form13-2023.csv
- Verified: headers and the first 700 bytes. 247,298,034 bytes, last modified
  2023-09-20. Same seven columns as the day file. Not downloaded.
- Licence: none stated.
- Yields: the same labels. About 1.6 million rows, estimated from the day
  file's 153 bytes a row; node counts not known. =reportCalendarOrQuarter=
  now varies, so =OWNS= is a time series.
- Oracle: =expected-counts= unchanged, if the rows can be held.
- Paired text: candidate 1, and =hands-on-lab/form13-raw/=, the raw filings
  the CSV was made from (over 1,000 objects, 136 MB in the first page of the
  listing).
- Questions:
  1. What did a manager add or drop between two quarters? (template)
  2. Which companies gained the most holders over the year? (template)
  3. Which managers hold alike? (algorithm: node similarity on the
     bipartite graph, then Louvain)
- Dirt: the value column changes scale inside the file. In the first rows a
  2022-09-30 position is 15,017,000 for 267,500 shares (56 a share) and a
  2022-12-31 position is 5,199,000,000 for 150,000 shares (34,660 a share).
  =form13/value-scale= of 1000 is right for the day file and wrong for
  quarters before 2022-12-31. Seen in two rows, not counted across the file.
- Breaks: everything this repository assumes. 247 MB as a vector of maps
  is over a gigabyte of heap; the load is minutes; =rows= as a =delay=
  cannot be the design.
- Smaller siblings in the same bucket, listed and not opened:
  =form13/2022-02-17.csv= (58 KB, another day), =form13/2021.csv= (52 MB),
  =form13/train.csv= and =form13/test.csv=.

** 3. SEC insider transactions (Forms 3, 4, 5)

- Page: https://www.sec.gov/data-research/sec-markets-data/insider-transactions-data-sets
- URL: https://www.sec.gov/files/datastandardsinnovation/data/insider-transactions-data-sets/2026q3_form345.zip
- Verified: downloaded and opened. 8,660,776 bytes, last modified
  2026-10-07; 53.6 MB unzipped, eight TSV tables, a metadata JSON and a
  readme. Needs a User-Agent that names the caller; no key.
- Licence: recalled, a US government work.
- Yields, from the 2026 Q3 file: 38,152 filings, 4,716 issuers by
  =ISSUERCIK=, 23,769 reporting owners by =RPTOWNERCIK=, 59,885
  non-derivative transactions.
  =(:Insider {cik})-[:FILED]->(:Filing {accession})-[:ABOUT]->(:Issuer {cik})=,
  with =RPTOWNER_RELATIONSHIP= (Director, Officer, TenPercentOwner) on the
  first edge and the transactions as dated properties or their own nodes.
- Oracle: distinct =ACCESSION_NUMBER=, =ISSUERCIK=, =RPTOWNERCIK=; rows of
  each table. Same technique as =expected-counts=, over three tables.
- Paired text: =FOOTNOTES.tsv=, 27 MB of free text keyed by accession number
  and footnote id. A footnote says in prose what the coded row says in
  columns, which is a checkable extraction.
- Questions:
  1. Who sold shares of an issuer in a given month, and how much? (template)
  2. Which people are insiders at more than one issuer? (template)
  3. Which issuers are joined by shared directors, and what are the
     clusters? (algorithm: projection onto issuers, then connected
     components or Louvain)
- Dirt: 727 amendments (=4/A=, =3/A=) that restate earlier filings. Five
  owner CIKs appear under more than one name. Dates are =31-JUL-2026=.
  Entities file as owners beside people. The newest two quarters moved from
  =/files/structureddata/= to =/files/datastandardsinnovation/=, so a URL
  built from a pattern breaks.
- Breaks: one file becomes a zip of related tables joined on accession
  number. In memory it fits. The load is tens of seconds, not two.
- Joining Form 13: no CUSIP here and no CIK there. A crude normalised name
  match found 925 of the day file's company names among 4,729 issuer names.
  That gap is an entity-resolution lab, not a defect.

* Software ecosystems

** 6. Clojars

- URLs: https://repo.clojars.org/feed.clj.gz ,
  https://repo.clojars.org/all-poms.txt.gz ,
  https://repo.clojars.org/stats/all.edn
- Verified: the first two downloaded, the third sampled. Feed 10,057,190
  bytes, 41.7 MB unzipped, last modified 2026-10-09 13:00 GMT, one EDN map
  a line, 33,567 lines. POM list 2,816,346 bytes, 328,935 paths. Stats
  4,753,754 bytes. The Clojars wiki says the lists are rebuilt hourly and
  the stats daily. No key.
- Licence: not found. The wiki page describes the files and states no terms.
- Yields: =(:Artifact {group, name})-[:HAS_VERSION]->(:Version)= from the
  feed, download counts from the stats. =DEPENDS_ON= is in neither: it is in
  the POMs, one request each.
- Oracle: lines in the feed for artifacts; the sum of =:versions= for
  versions; =all-poms.txt= as an independent count of versions.
- Paired text: =:description= in every feed line, and the README at
  =:scm :url=.
- Questions:
  1. Which artifacts did a group publish, and when was each last released?
     (template)
  2. What depends on a given library? (template, once POMs are in)
  3. Which libraries does the ecosystem rest on? (algorithm: PageRank over
     DEPENDS_ON)
- Dirt: =:homepage "http://example.com/FIXME"=, =:scm :tag "HEAD"=,
  SNAPSHOT versions, =#inst= tagged literals, and a stats key that is a
  request path: =["lein-scalac.lein-scalac.0.1.0.lein-scalac-0.1.0.jar?f=.m2" "clojars"]=.
- Breaks: the edges. Without POM fetches this is a catalogue, not a graph;
  with them it is a crawl of up to 328,935 requests. A subset (latest
  version of the 1,000 most downloaded) is a real file to cut once.
  It is EDN, which this repository reads natively and no CSV loader does.

  =(:Stop {id, lat, lon})-[:PART_OF]->(:Station)=,
  =(:Route)-[:SERVES]->(:Stop)=, =(:Stop)-[:NEXT {seconds}]->(:Stop)=,
  =(:Stop)-[:TRANSFER]->(:Stop)=.
- Oracle: rows per file for the nodes. =NEXT= is derived (consecutive

  1. Which routes serve Kendall/MIT? (template)
  2. Which stations are wheelchair accessible on the Red Line? (template)
  3. Fewest-stops or shortest-time path between two stations; which

- Dirt: stops are four things (stop, station, entrance, generic node)
  under one =location_type=; times run past 24:00:00; MBTA adds its own
  files to the standard.
- Breaks: =stop_times.txt= is 147 MB and three million rows. The rapid

- Yields: Northwind is the relational-to-graph case:
  =(:Customer)-[:PURCHASED]->(:Order)-[:ORDERS]->(:Product)-[:PART_OF]->(:Category)=,
  with =(:Employee)-[:REPORTS_TO]->(:Employee)= as a small hierarchy. The
  interaction network is one weighted undirected edge list. Network
  management is a data-centre hierarchy with dependencies.
- Oracle: Northwind's row counts, and its foreign keys: every order line
  must reach an order and a product.
- Paired text: Northwind has product and category descriptions; the rest
  has none.
- Questions, Northwind:
  1. What did a customer order? (template)
  2. Which products are bought together? (template)
  3. Which customers buy alike? (algorithm: node similarity)
- Dirt: the interaction file uses bare carriage returns as line endings,
  so =wc -l= says zero lines and =head -3= prints the file. Northwind is
  clean, which is its weakness. The movies set is a script and has no
  source file to be an oracle.
- Breaks: Northwind is seven files joined, none of them large. Offshore
  Leaks is two million nodes; the bucket has a 2023 copy as 626 MB of CSV
  under =offshore-leaks-fulldb/=.

What does not need to change: =expected-counts= is already the general
rule. A node count is the number of distinct key tuples; a relationship
count is the number of distinct (from key, to key, own key) tuples.
=verify= and =load!= are that rule and nothing about Form 13. The
analyses (=manager-degree=, =name-variants=, =odd-prices=) are the
dataset's, and stay with it.

Three things the table says:

- A self-relationship (12, 13, 14) breaks nothing in the rule and breaks
  =database-counts=, which matches each label once and assumes two.
- Derived edges (9) and unnested facts (5) are transforms, not
  descriptions. Either the map grows a function slot or those datasets get
  a small namespace that produces rows the map then describes. The second
  keeps the map data.
- An API (5, 7, 11, 12) is a dataset only after its response is saved.
  =:pin= is what turns it into a file that can be an oracle.
